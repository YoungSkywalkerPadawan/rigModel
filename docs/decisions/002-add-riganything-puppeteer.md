# 002：沿用冻结样本接入 RigAnything / Puppeteer

日期：2026-09-17。

用户在查看 UniRig 首轮结果后，明确要求拉取 RigAnything 和 Puppeteer，准备适配、依赖及权重，然后通知开 GPU。沿用已确认的 25 个持续旋转物体、65 根参考轴，不重新挑选样本。

选择各模型公开的骨架生成路径及官方权重，源码按 commit 和文件哈希固定。保留模型原生的输入处理和骨架后处理，再统一还原到世界坐标，沿用同一位置评分。Puppeteer 使用官方 demo 的 diverse-pose joint-token 配置；不引入其后续蒙皮及动画模型。RigAnything 仍保留官方生成函数中的采样点蒙皮头。

为复用已有可用 CUDA 环境，分别建立独立 venv，兼容的大依赖从 UniRig 环境只读链接。Puppeteer 的 PyTorch / CUDA 版本与官方环境不同，CPU 预检通过只代表可以开始 GPU 验证；首个 GPU 前向失败时先查兼容性，不能将环境故障计作模型效果结论。另一选择是重新搭建官方完整环境；目前先保留现有环境及版本清单。

AutoDL 的 CPU 模式只有半核，Puppeteer 的 SDF 预处理改用本地两个 CPU 进程，调用同一适配函数和官方实现。与服务器先完成的 13 例逐数组对比完全一致后，回传完整 25 例，保留原服务器部分结果作为证据。

这次增加对照模型不等于决定训练、替换旧 v29 或结束该研究方向。新增模型效果须等待实际 GPU 输出和离线评分。成功、停止标准及后续投入仍由用户决定。
