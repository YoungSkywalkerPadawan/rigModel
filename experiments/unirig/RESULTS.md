# UniRig 首轮实验记录

## 2026-09-17：CPU 准备

**目的**：为用户确认的 25 个持续旋转物体准备 UniRig 骨架候选推理，之后与 65 根已有机械参考轴比较位置。

**条件**：官方 UniRig 源码 `6793c6640ff01c8fb389f3993434124bb43d2933`；公开 Articulation-XL2.0 骨架权重 revision `36842e2b5947e9e60f89275b83208c8e74071c63`。AutoDL 当前 CPU 模式、0.5 核、2 GiB 内存。无训练，无 GPU 推理。

**结果**：1,439,617,174 字节骨架 checkpoint 及 644 字节 OPT config 均通过官方文件标识校验。25 个输入全部完成，每例 65,536 点，合计 1,638,400 点；源几何/标注与冻结基准逐例核对。585 个权重张量键与形状严格匹配，网络参数量 360,130,048。CPU 预检返回 `READY_FOR_GPU`，`gpu_available=false`、`gpu_inference_run=false`。

**结论**：依赖、权重、输入和 CPU 可验证的网络结构均已准备好，可以通知用户开启 GPU。尚未产生模型候选或准确率，不能将 CPU 准备称为推理成功。

**局限**：CPU 内存有限，完整模型加载与 CUDA 前向留到用户开启 GPU 后。已知参考为几何整理标注；尚未证明绑骨位置适合机械轴心。

准备时补装匹配 PyTorch 2.4 / CUDA 12.4 的 torch-cluster。最初继承旧环境时出现旧 UniPhysGen 应用的 Transformers 固定版本冲突；将新环境共享依赖与旧应用隔离后 `pip check` 通过，旧环境未修改。

权重全量哈希读取留下约 1.44 GB 文件缓存，曾导致 CPU 模式导入 PyTorch 的进程被终止。只对已验证权重使用 `posix_fadvise(DONTNEED)` 释放其干净文件缓存后，实例内存计数降至约 476 MB；PyTorch 单独导入峰值 RSS 376,468 KiB，随后完整预检通过。没有修改模型文件或放宽实例资源限制。Open3D 仅用于可选导出，本适配使用 trimesh，因此不安装到骨架运行环境。

离线契约验证覆盖坐标还原、沿轴平移不变性、骨架拓扑拒绝，以及失败/缺失候选保留分母。GPU 模型实际输出、速度、显存峰值与候选覆盖率均等待本轮开卡后记录。
